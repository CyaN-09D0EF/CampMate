# 발표 및 개발 체크리스트

[프로젝트 소개로 돌아가기](../README.md)

현재 저장소를 기준으로 작성했습니다. 계획 기능을 구현 완료 기능과 구분하여 발표 자료에 반영하세요.

## 시연 전 확인

- [ ] Java 21, Tomcat 10.1 및 DB 실행
- [ ] 메인 이미지와 초기 상품 4개 표시
- [ ] 기존·신규 아이디 중복 확인
- [ ] SMTP 설정 후 테스트 수신 주소로 인증 메일 수신 확인
- [ ] 새로 가입한 계정으로 로그인·이름 표시·로그아웃 확인
- [ ] 발표 자료에 담당자·역할·개발 기간·실제 화면 캡처 추가

이 체크리스트는 발표 직전 실행할 항목이며 자동 테스트의 통과 결과를 의미하지 않습니다. 기본 `test` 계정의 비밀번호는 평문이라 BCrypt 검증과 맞지 않습니다.

## 구현 예정 영역

- 캠핑장 검색 결과와 `/camp/search` 서버 처리
- 상품 전체 목록과 등록·상세·거래 흐름
- 커뮤니티 및 고객센터 페이지
- 자동화된 테스트와 재현 가능한 빌드 도구 설정

현재 `productList.jsp`, `community.jsp`, `cs.jsp`는 메뉴에서 연결하지만 저장소에 존재하지 않습니다.

## 우선 개선 항목

| 우선순위 | 항목 | 완료 기준 |
| --- | --- | --- |
| 높음 | DB·SMTP 설정 외부화 | 인증 정보가 코드에 없고 외부 설정으로 실행 가능 |
| 높음 | 저장소에 포함된 실제 인증 정보 정리 | 실제 자격 증명이라면 소유자가 폐기·재발급하고 노출 이력 검토 |
| 높음 | 가입 시 이메일 인증 서버 검증 | 요청의 hidden 값 대신 인증된 세션과 가입 이메일 일치 여부 검증 |
| 높음 | 인증 코드 남용 방지 | 안전한 난수 생성, 재전송·시도 횟수 제한, 성공한 코드 폐기 |
| 보통 | 초기 계정 비밀번호 형식 | 초기 데이터도 BCrypt 기반 로그인과 일치 |
| 보통 | DB 자원 및 오류 처리 | 연결을 확실히 해제하고 DB 실패를 정상 빈 목록과 구분 |
| 보통 | JSP·Servlet 역할 정리 | 요청 처리를 Servlet으로 옮기고 중복 화면 코드 정리 |

위 항목은 코드 검토로 파악한 후속 개발 과제입니다. 이번 문서 정리에서는 애플리케이션 동작이나 DB 데이터를 변경하지 않았습니다.
